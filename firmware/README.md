# Firmware

Firmware is developed with STM32CubeIDE and STM32 HAL.

Current project layout:

```text
firmware/
  common/      Shared CAN driver, ISO-TP core, and portable UDS service core
  ecu-f407/    STM32F407ZGT6 node
  ecu-f103/    STM32F103C8T6 node
```

The Week 1 firmware nodes currently implement:

- CAN1 at 500 kbps on PA12 (TX) and PA11 (RX).
- FIFO0 receive interrupt with an accept-all standard-frame filter.
- Periodic transmission of diagnostic ID `0x123` with one data byte.
- Received `0x123` data bit mirrored to PF9 on F407 and PC13 on F103.

Both current development boards provide only the MCU CAN controllers. CANH/CANL
are generated by the two external SN65HVD230 transceiver modules.

The F103/F407 filter-bank allocation is documented in
`docs/f103_filter_14_bank_design.md`.

The Week 4-5 portable UDS core is implemented in:

- `firmware/common/uds_server.h`: configuration/state data and public API.
- `firmware/common/uds_server.c`: `0x10`, `0x22`, `0x27`, `0x2E`, `0x31`,
  `0x3E`, DID lookup, security/routine state, S3 timeout, and negative
  responses.
- `firmware/common/uds_did_db.c`: F407/F103 DID database and per-ECU
  VIN/hardware values.
- `firmware/common/param_store.c/.h`: CRC-protected parameter snapshot.
- `firmware/common/param_log.c/.h`: append-only snapshot log and startup
  compaction.
- `firmware/ecu-f407/Core/Src/app_param_storage.c`: F407 Sector 11 adapter.
- `firmware/ecu-f103/Core/Src/app_param_storage.c`: F103 last-page adapter.
- `firmware/common/uds_reference_routines.c`: legacy no-hardware reference
  routine callbacks.
- `firmware/common/uds_ecu.c`: application-facing wiring for the DID database,
  routines, and server configuration.

The UDS core does not call HAL. Both applications call `UdsEcu_Init` and
`UdsEcu_Tick`. Responses flagged as `UDS_PROCESS_RESPONSE_PENDING` are sent
through ISO-TP, then `UdsEcu_PollPending` advances the routine and produces the
final response without requiring the tester to repeat the request.

F407 reserves Flash Sector 11 (`0x080E0000-0x080FFFFF`); F103 reserves its last
1 KB page (`0x0800FC00-0x0800FFFF`). Runtime DID writes append 80-byte snapshots
and never erase flash; startup compaction runs before the IWDG and WWDG are
enabled. Routine `0xFF00` appends an empty snapshot as a logical parameter clear.

The Week 3 ISO-TP core is implemented in:

- `firmware/common/isotp.h/.c`: SF/FF/CF/FC, sender/receiver state machines,
  BS/STmin flow control, and `N_As/N_Bs/N_Cr/N_Ar` timeouts.
- `firmware/common/isotp_bench.h/.c`: fixed 100-byte hardware bench payload.
- `firmware/common/project_dbc.c/.h`: generated DBC signal codecs.
- `firmware/common/dbc_bench.c/.h`: isolated `EngineData`/`VehicleStatus` senders.
- `firmware/common/background_probe.c/.h`: background sequence-gap counters.
- `firmware/common/uds_fault_test.c/.h`: test-only DTC/NRC/comm-loss hook.
- `firmware/common/stress_master.c/.h`: board-internal UDS and load test helper.

Both applications route diagnostic frames through `Isotp_RouteFrame()`, pass
reassembled requests to `UdsEcu_Process`, and transmit the response through the
TP sender.

Build both nodes from the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File firmware\ecu-f407\build.ps1
powershell -ExecutionPolicy Bypass -File firmware\ecu-f103\build.ps1
```

The scripts resolve `arm-none-eabi-gcc` from `ARM_GCC_BIN`, `PATH`, or common
STM32CubeIDE installation directories. Set `ARM_GCC_BIN` only when automatic
discovery cannot find the toolchain.

Build the 100-byte node bench variants with `-IsotpBenchTx` or
`-IsotpBenchRx`.

Isolated Week 7/8 hardware modes:

```powershell
powershell -ExecutionPolicy Bypass -File firmware\ecu-f407\build.ps1 -DbcBench
powershell -ExecutionPolicy Bypass -File firmware\ecu-f103\build.ps1 -DbcBench
powershell -ExecutionPolicy Bypass -File firmware\ecu-f407\build.ps1 -BenchTest
powershell -ExecutionPolicy Bypass -File firmware\ecu-f103\build.ps1 -BenchTest
powershell -ExecutionPolicy Bypass -File firmware\ecu-f407\build.ps1 -StressMaster
powershell -ExecutionPolicy Bypass -File firmware\ecu-f103\build.ps1 -StressMaster
powershell -ExecutionPolicy Bypass -File firmware\ecu-f407\build.ps1 -LoadGenerator -LoadPeriodUs 250 -PeerStability
powershell -ExecutionPolicy Bypass -File firmware\ecu-f103\build.ps1 -PeerStability
powershell -ExecutionPolicy Bypass -File firmware\ecu-f407\build.ps1 -LoadGenerator -LoadPeriodUs 888 -PeerStability -FrameLossBench -FrameLossFrames 5000
powershell -ExecutionPolicy Bypass -File firmware\ecu-f103\build.ps1 -LoadGenerator -LoadPeriodUs 888 -PeerStability -FrameLossBench -FrameLossFrames 5000
```

These switches are mutually exclusive where they change bus behavior. Formal
builds must be rebuilt and reflashed after hardware tests.

The build scripts use the GNU ARM GCC bundled with STM32CubeIDE and emit
ELF, BIN, and HEX files under each node's `Build/` directory.

Target layer structure:

```text
Application
  -> UDS service layer (0x10/0x22/0x2E/0x27/0x31)
  -> ISO 15765-2 TP layer
  -> CAN driver layer
  -> STM32 HAL
```
