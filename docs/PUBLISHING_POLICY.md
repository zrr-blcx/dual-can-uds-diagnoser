# GitHub 发布规范（项目二）

## 通用原则

- 每周 GitHub 只发布三样：本周代码、本周测试结果、一份能说明“做了什么”的文档。
- 本地保留：学习笔记、视频链接、购物价格、个人日志、AI 提示词。
- 永远不发：简历、课程资料、淘宝链接、COM 口调试截图、个人路径和真实个人信息。
- `开发日志/` 可以发布，但只写“技术进展 + 代码变更 + 下周计划”，不写“今天看了什么视频、学了多久”。

## 每周发布清单

### 第 1 周：硬件与 CAN 基础

- 发布：F407/F103 的 CubeIDE 工程骨架、`CAN_Init / CAN_SendFrame / CAN_RxCallback` 驱动、接线文档初版。
- 本地保留：板载收发器型号确认过程、万用表测量记录、视频学习笔记。
- 不要发：购物清单价格、个人学习计划。

### 第 2 周：错误处理与 Bus-Off

- 发布：错误统计代码、Bus-Off 恢复函数、IWDG/WWDG 配置、Bus-Off 注入测试记录。
- 本地保留：CAN 错误状态机学习笔记。
- 不要发：未整理的调试截图。

### 第 3 周：ISO-TP

- 发布：C 语言 TP 层源码、SF/FF/CF/FC 状态机、100 字节多帧互传测试代码与结果。
- 本地保留：协议讲解笔记、抓包分析过程。
- 不要发：大量原始抓包文件，只放结论或少量示例帧。

### 第 4 周：UDS 框架 + 0x10/0x22

- 发布：UDS 服务分发框架、DID 数据库、会话控制与读 DID 代码、单节点联调脚本。
- 本地保留：UDS 协议学习笔记。
- 不要发：不完整的临时调试代码。

### 第 5 周：0x27 + 0x2E + 0x31

- 发布：安全访问、写 DID、例行控制代码、NRC 测试用例表、双节点联调记录。
- 本地保留：Seed/Key 算法思考过程。
- 不要发：与项目无关的课程笔记。

### 第 6 周：Python 诊断仪 V1.0

- 发布：CLI 源码、`requirements.txt`、README 快速开始、命令示例、诊断仪 Alpha 说明。
- 本地保留：CANable 驱动排查过程、个人使用习惯配置。
- 不要发：本机 COM 口编号和硬件序列号。

### 第 7 周：DBC + 双节点调度

- 发布：DBC 文件、DBC 解析生成脚本、生成的 C 结构体、双节点调度器、调度测试。
- 本地保留：CANdb++ 使用学习笔记。
- 不要发：手工临时修改的 DBC 中间版本。

### 第 8 周：压力测试 + 故障注入

- 发布：负载模拟器、压力测试框架、故障注入脚本、低负载基线报告。
- 本地保留：个人排查记录。
- 不要发：未清洗的原始日志，先去掉时间戳噪音和个人信息再上传 CSV。

### 第 9 周：Bus-Off 验证 + 稳定性

- 发布：Bus-Off 恢复测试报告、4 小时稳定性报告、Bug 修复提交、重构后的代码结构。
- 本地保留：长时间运行的临时截图。
- 不要发：失败过程细节，只发最终结论和修复记录。

### 第 10 周：终测 + Release

- 发布：10,000 帧测试报告、README 双语版、架构和接线文档终版、`CHANGELOG.md`、`LICENSE`、GitHub Release `v1.0.0`。
- 本地保留：简历准备、面试问答稿、个人总结。
- 不要发：简历相关文件、未达标的测试结果；如果还没达标就继续标 `Target`。

## ROADMAP 维护

- 周计划只作为 `docs/ROADMAP.md` 存在，不每周修改。
- 只在里程碑完成后更新对应阶段状态。
